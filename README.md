# russia-blocked

Monthly monitoring of how Russian government websites can be reached from abroad and
whether web archives still preserve them, with a static web app that shows the results
since 2019.

Site: <https://ruarxive.org/russia-blocked/>

Since 2022 many sites of federal government bodies and their regional offices, courts,
election commissions and state information systems have been hidden behind geoblocking,
DDoS filters and WAFs. Foreign archives such as the Internet Archive cannot capture them, and Russia has
no mandatory archiving of public government websites. This project measures the scale
of the problem every month.

## What is measured

| Source | What | How often |
|---|---|---|
| Live probe from a vantage point outside Russia | DNS, ASN and country of the IP, TCP 443/80, TLS certificate and chain (Russian Trusted Root CA), homepage response classified as content / JS shell / WAF challenge / block page / empty / error, protection vendor, robots.txt | monthly |
| WHOIS (whois.tcinet.ru) | creation date and owner type of .ru/.su/.рф domains, to detect expired government domains taken over by third parties | every 90 days |
| Wayback Machine sparkline API | homepage captures per month and the best HTTP status class of each month, since 2019 | monthly |
| Wayback Machine snapshots | the last HTTP 200 homepage capture of each year, downloaded and classified with the same classifier as the live probe | once for past years, monthly for the current year |
| Common Crawl Host Index | pages fetched per host and crawl by HTTP status class (crawls of December 2021 to April 2025) | once, new crawls when the index adds them |

Headline shares are computed over the **2021 cohort**: sites with at least one HTTP 200
capture in 2021 that still exist as government sites (their domain resolves and was not
taken over). The methodology section of the web app explains the definitions and limits.

## Layout

```
rublocked/            Python package (python -m rublocked <command>)
  registry.py         selects significant hosts from the Orgview export into data/registry/domains.csv
  probe.py            live probe (asyncio, httpx, dnspython)
  fingerprint.py      response classifier, protection vendor, spam and parking detection
  whois.py            WHOIS of registrable domains
  wayback.py          Wayback sparklines and snapshot classification (polite, adaptive pacing)
  commoncrawl.py      Common Crawl Host Index via DuckDB over HTTPS
  build.py            aggregates everything into site/data/
data/
  registry/           Domains-Orgview.csv (source), domains.csv (monitored hosts)
  probes/             YYYY-MM.jsonl.gz probe results + YYYY-MM.meta.json (vantage point)
  whois/              whois.jsonl.gz
  wayback/            sparkline/<host>.json, snapshots.jsonl.gz
  commoncrawl/        hosts.csv.gz, crawls.csv
site/                 static web app (index.html, assets/, data/ generated by build)
scripts/monthly.sh    the monthly run
```

## Setup

```bash
uv venv .venv
uv pip install -p .venv/bin/python -r requirements.txt
```

The registry is built from `data/registry/Domains-Orgview.csv`, the Orgview export of the
federal part of the [govdomains](https://github.com/infoculture/govdomains) base: about
7,700 hosts with a curated type, organization, region, status and archive priority. Only
significant sites are kept:

* main sites of federal bodies, commissions and councils, state information systems,
  open data portals, state institutions and programmes;
* regional offices of federal agencies at the level of a region (district police
  departments and other units below it are left out);
* courts of the regional level and above (regional, republic and arbitration courts,
  appeal and cassation courts) and the election commissions of the regions;
* nothing marked as an alias of another host, inactive, empty, redirecting,
  password-protected or not worth archiving, and no technical hosts (mail, test servers,
  personal account logins, APIs), language, mobile or accessibility versions.

`python -m rublocked registry` logs how many hosts each rule left out. The built
`data/registry/domains.csv` is kept in the repository, so the registry only needs a
rebuild when the source list changes. Common Crawl data is backfilled for hosts added
to the registry; `data/commoncrawl/queried.txt` lists the hosts covered by every crawl.

## Commands

```bash
.venv/bin/python -m rublocked registry      # rebuild the registry
.venv/bin/python -m rublocked probe         # live probe of all hosts (about 45 min)
scripts/probe-ru.sh                         # the same probe from Russia, in the VPN container
.venv/bin/python -m rublocked whois         # WHOIS refresh
.venv/bin/python -m rublocked wayback       # Wayback sparklines (1-3 h, archive.org rate limits)
.venv/bin/python -m rublocked snapshots     # classify yearly Wayback snapshots
.venv/bin/python -m rublocked commoncrawl   # Common Crawl host statistics (about 8 min per crawl)
.venv/bin/python -m rublocked build         # write site/data/*.json
.venv/bin/python -m rublocked monthly       # all of the above in order
```

`probe --hosts a.ru b.ru` re-probes only the given hosts and merges them into the
current month's file.

Preview the site:

```bash
python3 -m http.server 8791 --directory site
```

## Monthly run

`scripts/monthly.sh` runs `python -m rublocked monthly` and writes a log to `logs/`.
The probe must run from a network outside Russia; the vantage point (IP, country,
network) is recorded in `data/probes/YYYY-MM.meta.json` and shown on the site, so runs
from different networks stay comparable. The probe connects directly and ignores
`HTTP(S)_PROXY`.

### Check from Russia

Right after the foreign probe, `monthly` runs `scripts/probe-ru.sh`: the same probe from a
Russian network, to tell blocking of foreign addresses apart from a site that is down for
everyone. The AmneziaWG tunnel (WireGuard with traffic obfuscation, built from
[amnezia-vpn](https://github.com/amnezia-vpn) sources) runs inside a Docker container
(`docker/probe-ru/`), so it
never changes the routing of this machine or of the collectors running meanwhile. The
repository is mounted into the container; results go to `data/probes/ru/YYYY-MM.jsonl.gz`
with the vantage point in `YYYY-MM.meta.json`. Names are resolved through Yandex DNS
(77.88.8.8), and the default concurrency is 10, as one VPN exit carries all requests.

* The VPN config is read from `secrets/rusgate.conf` (or `RU_VPN_CONF`). `secrets/` is in
  `.gitignore`; the config holds a private key and must never be committed. The image does
  not contain it, it is mounted read-only at run time.
* Docker Desktop must be running. Without the config the step is skipped with a warning;
  `monthly --skip probe-ru` skips it on purpose.
* Both probes refuse to run from the wrong side of the border: the Russian one stops unless
  the exit IP is in Russia, the foreign one stops if it is.
* `scripts/probe-ru.sh --limit 50` or `--hosts a.ru b.ru` passes arguments to the probe.

The site compares the two views when the month has a Russian probe: a site that does not
open from abroad but opens from Russia counts as closed to foreign visitors only.

To run it locally on macOS once a month, install the launchd job:

```bash
cp scripts/org.ruarxive.russia-blocked.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/org.ruarxive.russia-blocked.plist
```

## Deploy

The site is served by GitHub Pages at <https://ruarxive.org/russia-blocked/>.
`.github/workflows/pages.yml` runs on every push to `main` (and by hand from the Actions
tab): it installs the requirements, runs `python -m rublocked build` on the committed
`data/` (no network access needed) and deploys `site/` with the generated `site/data/`.
`site/data/` is not kept in the repository, so after the monthly run commit and push
`data/` to update the site.

The repository's Pages source is "GitHub Actions" and it has no custom domain of its
own: the organization site `ruarxive.github.io` is served at `ruarxive.org`, so project
sites of the organization are served under its paths. All site links are relative, and
the absolute URL is only set in the canonical and Open Graph tags of `site/index.html`,
`site/sitemap.xml`, `SITE_URL` in `site/assets/app.js` and the crawler User-Agent in
`rublocked/common.py`.

## Limits

* Without a vantage point inside Russia, geoblocking cannot be told apart from a site
  that is down for everyone with certainty. A TCP timeout on an IP in a Russian network
  with working DNS is almost always filtering of foreign addresses.
* The Wayback metrics use the homepage only. A site whose homepage is captured can
  still have most of its pages missing from the archive.
* The registry reflects government domains of 2020–2022. New domains created later are
  not monitored unless added to the source lists.

## Feedback

The site has a feedback form for errors in the data, suggestions and other messages.
It has no backend: the form opens a prefilled issue in
[ruarxive/russia-blocked](https://github.com/ruarxive/russia-blocked/issues) or a
prefilled email in the visitor's mail app. The repository URL and the email address are
set at the top of `site/assets/app.js`.
